# UIシステムの抽出

対象（URL・npmパッケージ・GitHubリポジトリ）からデザイントークンを取り出し、
`skills/<名前>/SKILL.md` として保存する。完成例は `skills/dads/` を見ること。

## 原則（card-spend-viz で得た知見）

1. **実物のトークンだけを書く。目視で推測したHEXは書かない。**
   公式サイトに値が載っていないことは多い（デジタル庁もそうだった）。
   npmパッケージ・GitHubの tokens.css/json・CSSカスタムプロパティを探す。
   どうしても計算値しか無いときは `確度: 実測` / `確度: 推定` を必ず付ける。

2. **1スキル＝1システム。混ぜない。**
   「AI感」の正体は汎用表現の寄せ集め。複数システムのいいとこ取りをした時点で失敗する。
   使う側が1つ選んで丸ごと採用できる形にする。

3. **チャート配色はそのまま使えないことが多い。**
   行政・企業のデザインシステムはUI向けで、データ可視化パレットを持たないのが普通。
   プリミティブから4色選び、**dataviz スキルのバリデータで検証してから**書く。
   検証コマンドと結果（CVD ΔE・コントラスト）をスキルに残す。
   例: 緑×黄土は色覚特性で区別不能（ΔE 6.6）→ Cyanに差し替えて19.5、のような判断を記録。

4. **「無い」ことも書く。**
   DADSはウェイトが400/700しか無い。500を使ったら準拠ではない。
   体系に存在しない値の使用は逸脱だと明記する。

5. **ライセンスを確認してから置き場所を決める。**
   - npm なら registry の `license` フィールド、リポジトリなら LICENSE ファイル
   - MIT / Apache-2.0 等の再配布可 → `skills/`（公開リポジトリに入る）
   - **ライセンス記載なし・独自規約・ブランドガイドのみ → `local/`（gitignore済み、自分専用）**
   - 判定結果と根拠をスキルの冒頭に書く
   実例: デジタル庁は MIT なので skills/、PayPay の npm はライセンス記載なしなので local/。

## 手順

0. **ライセンス確認**（上の原則5）。置き場所（skills/ か local/）をここで決める。
1. **トークン源を特定する**（優先順）
   a. npm: `curl -sL https://unpkg.com/<pkg>@latest/dist/tokens.css`
   b. GitHub: design-tokens / tokens.json / *.css を探す
   c. サイトのCSS: `curl -s <url>` → `:root` の custom properties / Tailwind config
   d. 計算スタイル: ブラウザ自動化で getComputedStyle（これは `確度: 推定`）
2. **抽出する項目**
   - 色: プリミティブスケール全段 / セマンティック（success, error等）/ 面と罫線
   - 書体: family・使うウェイトの列挙・基準サイズ・行間
   - 形: 角丸の段階 / 影 / 罫線の太さ
   - 余白: スペーシングスケール
   - 文言のトーン: 敬体か、絵文字の有無、ボタンの動詞（観察できる範囲で）
3. **チャート4色を選定して検証する**
   `node <dataviz>/scripts/validate_palette.js "#..,#..,#..,#.." --mode light --surface "#見つけた面色"`
   ライト・ダーク両方。落ちたら別の段を試す。結果の数値をスキルに書く。
4. **`skills/<名前>/SKILL.md` に書き出す**（frontmatter必須・下のテンプレート）
   取得した tokens.css 等の原本も同じフォルダに置く。
6. **install.sh を実行**して ~/.claude/skills に反映する。

## 書き出しテンプレート

```markdown
---
name: <slug>
description: <システム名>のUIトークン。<いつ使うか>。
---

# <システム名>

出所: <URL / npmパッケージ名@version>（取得日 YYYY-MM-DD、確度: 実測 or 推定）

## 使い方
このスキルを読んだら、以下の値を **そのまま** 使う。他システムと混ぜない。
体系に無い値（例: 中間ウェイト）を発明しない。

## 色 / 書体 / 形 / 余白 / チャート4色（検証結果つき） / 文言のトーン
（各セクション：表で。チャート色には validate_palette の数値を残す）

## この体系に無いもの
（存在しないウェイト・使ってはいけない色など）
```
