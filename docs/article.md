# デジタル庁デザインシステムには「グラフの色」がない。検証して作って、AIスキルにした

AIにWebサイトやアプリの画面を作らせると、なぜか「どこかで見た画面」になる。
紫のグラデーション、意味もなく置かれた絵文字、全部同じ丸みのカード。
いわゆる「AIっぽいデザイン」だ。

最近noteで、その正体を言い当てた記事が回っていた。いわく、AIっぽさの正体は
装飾ではなく、そのプロダクト固有の判断基準が見えないこと。だから「いい感じにして」と
頼むほど悪化する。処方箋は、実在する企業や行政の「デザインシステム」——色・文字・余白
などの判断基準を丸ごとまとめたルールブック——をひとつ選んで、そのまま採用すること。
複数を混ぜないこと。

納得したので、自作の家計簿アプリで実践してみた。選んだのはデジタル庁の
デザインシステム（DADS）。行政サービスの画面のために作られた、いま日本で一番
参照しやすい体系だ。ところが実際にやってみると、記事には書かれていない壁が2つあった。

## 壁1　公式サイトに色の数値が載っていない

デザインの色は「#0017C1」のような16進数のコード（HEX値）で指定する。
ところがDADSの公式サイトには色見本の画像だけがあって、このコードがどこにも
書いていない。「詳細はFigmaを参照」とある。

答えは意外な場所にあった。デジタル庁が開発者向けに配布しているnpmパッケージ
（プログラム部品の公式配布物）に、全色のコードが入っている。コマンド一発で取り出せて、
ライセンスはMIT、つまり誰でも自由に使っていい。

取り出してみると、サイトからは分からないことがいろいろ書いてある。

- 文字の太さは400と700の2種類しか存在しない（中間の500を使ったら、もうDADS準拠ではない）
- 薄いグレーの文字は #767676 が下限（白地とのコントラスト比4.5:1。これより薄いと読みにくい人が出る）
- 角の丸みは 4 / 8 / 12 / 16 / 24 / 32px の6段階だけ

「体系に無いものを知る」ことが、混ぜないための第一歩だった。

## 壁2　グラフの色が決められていない

DADSは行政の申請画面のような「文書とフォーム」のための体系なので、グラフ用の色が
定義されていない。家計簿アプリはグラフだらけだ。自分で選ぶしかない。

そこで公式の色の中から青・橙・緑・黄土の4色を選んだのだが、思わぬ問題が見つかった。
日本人男性の約5%（20人に1人）は赤と緑の系統が区別しづらい色覚タイプで、その見え方は
計算で再現できる。試しに4色を変換してみると、緑と黄土がほぼ同じ色に見えてしまう。
色の差を表すΔEという数値で6.6——見分けやすさの基準は8以上だ。

緑を水色系に差し替えて再計算したら ΔE 19.5。誰の目にも別の色になった。

ライト（白地）: #3460FB / #E25100 / #00A3BF / #B78F00
ダーク（黒地）: #4979F5 / #E25100 / #00A3BF / #B78F00

見た目の好みではなく計測で決める。ここまでやって初めて「体系に乗った」と言えると思う。

## 調べた結果を「AIスキル」として公開した

ここまでの値と判断を、次に使うときにAIへそのまま渡せる形にした。Claude CodeやCursorの
ようなAIコーディングツールには「スキル」——特定の作業のやり方を書いた指示書を
読み込ませる仕組み——があり、その形式でまとめてGitHubに公開している。

https://github.com/T-Yamada7/ui-skills

使うときは「dadsスキルに従って設定画面を作って」と頼むだけ。中身はただのMarkdown
テキストなので、どのAIツールでも、プロンプトに貼るだけでも機能する。

## 抽出の方法論

リポジトリの本体は、他のデザインシステムを自分で調べてスキル化するための手順書
（extract-ui-system）の方だ。原則は5つ。

- 実測値だけを書く。画面を目で見て推測した色コードは書かない。出所・バージョン・取得日を明記する
- 1スキル=1システム。混ぜない
- グラフの色は、色覚とコントラストの検証を通った値だけを載せる。検証の数値も残す
- 「体系に無いもの」も書く
- ライセンスを確認してから公開する（実はPayPayの色も公式配布物から取り出したが、ライセンスの記載が無かったので公開版には入れていない）

自動で何でも抽出してくれるツールは既にある。このリポジトリは逆に、少数を検証して、
判断の記録ごと残す。AIに渡す判断基準は、量より確度だと思う。

## まとめ

- 「AIっぽいデザイン」の正体は、判断基準の不在。実在のデザインシステムを丸ごと採用するのが近道
- デジタル庁デザインシステムの色コード（HEX値）は、公式サイトではなくnpmの配布物（デザイントークン）にある
- ただしグラフ・チャート用の配色は無いので、色覚多様性とコントラスト比を検証して自分で選ぶ必要がある
- 検証済みの結果はGitHubで公開している。同じ壁の前にいる人はどうぞ
